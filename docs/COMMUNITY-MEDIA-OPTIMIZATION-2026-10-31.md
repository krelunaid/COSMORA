# Community media optimization — 31 October 2026

## Current release 1.0.7

JPEG files larger than 500,000 bytes are re-encoded at most 2048 px at quality 0.82 if decoding succeeds and the result is smaller; HEIC/HEIF is converted where the device can decode it. PNG, WebP and videos are preserved. The original file is retained if conversion fails. Feed and home use the complete signed image even for grid thumbnails. Therefore the release does not ensure fast loading and doesn't retrofit old images.

## Thumbnail work, local only

The client now supports optional `thumbnail_url` for grid and home, with original-image fallback on a missing or failed preview; the detail view still loads `url` (the original). This client code has not been shipped. The recovery service has a proposed, un-deployed server-owned thumbnail registry migration and an optional feed lookup. The registry uses RLS with no client grants and checks that the original path is still the one referenced, and that the thumbnail is the exact sibling filename. Feed tests cover visible/blocked posts, original preservation, and fallback on stale or unavailable metadata; 25 edge tests and 317 application tests pass. The migration has NOT been applied and the server code has NOT been deployed.

Six local 800px thumbnails were derived from the existing local 1600px candidates and sanitized using the existing photo privacy sanitizer. Their combined size is 1,095,681 bytes, versus 21,297,045 bytes for their originals. No files have been uploaded. `scripts/generate-legacy-thumbnails.mjs` is in the backend recovery workspace and writes only to a mode-0700 local folder; it does not mutate remote storage.

Critical outstanding work: trusted automatic generation from each actual media file (do not accept an unverified user-supplied preview as moderated content), resource-limit controls and tests on malformed/huge files, atomic/retry-safe storage + registry insertion, cleanup of derivatives on media deletion and account deletion, backfill of existing objects with source consistency verification, uploading private derivatives, deployment of registry and feed in the proper order, and new store packages. Supabase free plan transform endpoint returned FeatureNotEnabled. WASM image conversion was proven only on local Node, not the hosted edge runtime; Supabase documents resource limits on large images. Do not deploy the draft until those gates are closed.

## Production backfill completed

The stronger eight previews are now stored in the server-only `community_media_previews` table (422,885 JPEG bytes total). This supersedes the earlier draft storage-object registry: previews are attached by a cascading FK to post_media, whose FK cascades from community_posts and auth.users. No derivative storage objects are created. Eight sources were re-fetched and SHA-256 verified against the local source manifest before publication. Original storage objects were not replaced. Schema was applied using the dashboard SQL editor; the migration file is retained locally but was not added to the migration ledger.

The Edge Function entrypoint was replaced with an esbuild bundle of the current reviewed local source (external Supabase/Zod imports retain the existing pinned import map). The feed reads only small preview metadata and supplies one-hour HMAC-scoped capability URLs. The JPEG endpoint verifies the signature, current media, ACTIVE post, exclusion of review fixtures, and exact original path before reading the preview bytes. Direct table access is revoked from anon/authenticated. No per-image secret is added or granted to clients; the existing runtime secret signs a context-separated capability. The same bearer-link sharing limitations of original signed Storage URLs apply; bilateral blocks are enforced before capability issuance in the feed. Responses remain private/no-store. Deleted/hidden/stale media returns 404.

30 Edge tests and TypeScript passed. Production HTTP checks fetched all eight previews, compared their SHA-256 values to the intended JPEGs, and checked invalid capabilities (404), unauthenticated account/seller (401), and anonymous saved feed (401). Evidence: recovery workspace outputs/preview-live-checks.json and outputs/preview-tests.log. The endpoint and feed are live; full-size originals remain available through the existing media.url field. Community grid/home use thumbnail_url only in compatible app bundles, including 1.0.8; older apps may continue loading originals. Actual physical-device rendering/timing is not verified. Automatic generation of previews for future uploads is NOT enabled by this backfill and remains future work; the existing newer-client JPEG/HEIC compression is separate.
